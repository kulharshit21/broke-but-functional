Build a complete, polished, local-first web app called “Broke But Functional — Survive the Month”.

This is not a basic expense tracker. Build it like a real consumer fintech product for Gen Z users in India who have only ₹10,000 to survive 30 days. The app must make every financial decision feel real, connected, and slightly intense: balance, daily allowance, savings goals, subscriptions, unexpected expenses, risk, and monthly forecast should all update together.

The final result should feel handcrafted, specific, and product-grade. It must not feel like a generic AI-generated dashboard. Avoid boilerplate language, placeholder copy, lorem ipsum, fake futuristic branding, or vague “insights” screens.

PRIMARY GOAL
Create an interactive experience where the user can:
1. See how much money they can safely spend today.
2. Simulate a financial decision before applying it.
3. See how that decision affects:
   - remaining balance
   - safe-to-spend today
   - daily allowance
   - month-end forecast
   - savings goals
   - subscriptions
   - unexpected expense risk
   - financial risk score
   - overall financial health score
4. Apply the decision only after understanding the consequences.
5. Track the full 30-day month with a clear cashflow forecast and danger days.

FINANCIAL ENGINE
Build a pure TypeScript money engine in separate files. All derived values should be calculated from state and should be testable.

Implement these selectors/functions:

1. getCurrentBalance(state)
   Starting balance plus completed income minus completed expenses.

2. getDaysLeft(state)
   monthLength - currentDay + 1
   Treat current day as still usable.

3. getUpcomingCommittedTotal(state)
   Sum of all future non-optional commitments, active subscriptions due before month end, and protected goal contributions due.

4. getProtectedGoalReserve(state)
   Amount that should stay locked for protected savings goals.

5. getExpectedShockExposure(state)
   Sum of risk.amount * risk.probability for all active unexpected risks.

6. getShockReserve(state)
   A conservative reserve based on expected shock exposure.
   Use:
   min(1500, round(expectedShockExposure * 0.4))

7. getSafeToSpendToday(state)
   Use this formula:
   availableForDaily = currentBalance - upcomingCommittedTotal - protectedGoalReserve - shockReserve - minimumBuffer
   safeToSpendToday = max(0, floor(availableForDaily / daysLeft))

   If availableForDaily is negative, safeToSpendToday is 0 and show shortfall clearly.

8. getDailyAllowance(state)
   Same base logic as safe-to-spend but display it as average allowed daily spend.

9. getRunwayDays(state)
   Simulate future days using:
   - plannedDailySpend
   - upcoming commitments
   - active subscriptions
   - scheduled income
   - expected shocks only if the user chooses “include likely shocks”
   Count how many days the user can continue before balance falls below minimumBuffer.

10. getForecast(state, scenario?)
   Return a 30-day array with:
   - day
   - baselineBalance
   - scenarioBalance if scenario exists
   - committedOutflow for that day
   - income for that day
   - isDangerDay
   - isLowBalanceDay

   Forecast rules:
   - Start from current balance on currentDay.
   - For each remaining day, subtract plannedDailySpend.
   - Subtract scheduled commitments and subscriptions due that day.
   - Add scheduled income due that day.
   - If scenario is provided, apply the scenario action on its selected day.
   - Danger day = projected balance below minimumBuffer.
   - Low balance day = projected balance below minimumBuffer + 500.

11. getRiskScore(state, forecast)
   Return 0 to 100.
   Use weighted logic:
   - danger days count
   - projected negative balance
   - commitments due in next 7 days relative to balance
   - expected shock exposure relative to balance
   - subscription burden relative to safe-to-spend
   - lack of upcoming income when balance is low
   - recent overspend pattern

   Suggested implementation:
   - dangerDays * 3, capped at 30
   - negative month-end balance penalty, capped at 25
   - next7CommitmentPressure, capped at 20
   - shockExposurePressure, capped at 15
   - subscriptionPressure, capped at 10
   Clamp total between 0 and 100.

   Risk labels:
   - 0 to 24: Steady
   - 25 to 49: Tight
   - 50 to 74: Risky
   - 75 to 100: Danger

12. getHealthScore(state, forecast)
   Return 0 to 100.
   Weighted score:
   - survival runway: 30%
   - cushion after commitments: 20%
   - savings goal progress: 15%
   - commitment coverage: 15%
   - spending discipline: 10%
   - shock readiness: 10%

   Health labels:
   - 0 to 39: Fragile
   - 40 to 69: Managing
   - 70 to 100: Stable

13. simulateDecision(state, action)
   Return a before/after comparison object including:
   - currentBalance
   - projectedMonthEndBalanceBefore
   - projectedMonthEndBalanceAfter
   - safeToSpendTodayBefore
   - safeToSpendTodayAfter
   - dailyAllowanceBefore
   - dailyAllowanceAfter
   - runwayDaysBefore
   - runwayDaysAfter
   - riskScoreBefore
   - riskScoreAfter
   - healthScoreBefore
   - healthScoreAfter
   - goalImpact
   - dangerDaysBefore
   - dangerDaysAfter
   - nextDangerDayBefore
   - nextDangerDayAfter
   - warningMessages
   - recommendation

- create custom scenario
- choose day
- choose amount
- choose category
- choose whether to include likely shocks
- see before/after comparison
- see warning messages
- apply or discard

Include these preset simulations:

   Expense ₹900, day 12, category fun.
2. “Pause OTT subscription”
   Saves ₹199, subscription pause.

   Expense ₹650, day 18, category health.

   Income ₹1200 on day 11, but adds transport cost ₹180 on day 11.

   ₹0 today, adds commitment ₹1500 on day 25, increases risk.

   Moves ₹239 payment 3 days forward, small risk increase.

   Saves ₹119.
